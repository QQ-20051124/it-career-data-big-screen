# 「岗位技能清单+学习资源推送」模块重构实施方案

> 目标：以本地静态资源知识库为核心，移除全部 DeepSeek 依赖，建立「本地库 → Coze → 本地兜底」三级匹配，新增全量岗位自检，双层链接校验，前端零空白、零报错。

---

## 一、当前状态分析（Phase 1 探索结论）

### 1.1 后端 `backend/routes/resources.js`（核心问题文件）
- **DeepSeek 残留**：第 49-52 行 `DEEPSEEK_API_KEY/API_BASE/MODEL`；第 128-210 行 `generateAIResources(skillName)` 调用 DeepSeek 生成资源（L2）。
- **三级匹配已存在但用错模型**：`matchSkillResources`（第 324-383 行）流程为 L1(DB) → L2(DeepSeek AI) → L3(知识库兜底)，需将 L2 改为 Coze。
- **数据源错位**：主数据源是 `learning-resources.json`（`loadResources`），而 `local-knowledge-base.json` 仅作 L3 兜底（`getKnowledgeBaseFallback`）。需求要求以 `local-knowledge-base.json` 为核心。
- **缺失功能**：无 `generateCozeResources`、无 `/self-check` 自检端点。
- **已有可复用**：`filterValidResources`、`quickCheckLink`（3h 缓存）、`checkLink`、`isSkillMatched`（严格标签匹配）、`hasTextAndVideo`、`sortBySourcePriority`、`sanitizeResource`、`/match-position` 端点框架。

### 1.2 后端 `backend/routes/ai.js`
- 仍含 `DEEPSEEK_API_KEY` 配置（第 11-14 行）和 `callDeepSeekFallback()`（第 255-349 行）。聊天流程：规则 → KB → Coze → **DeepSeek** → 本地兜底，需删除 DeepSeek 分支。

### 1.3 `backend/.env.example`
- 仍保留 `DEEPSEEK_API_KEY/API_BASE/MODEL` 三项配置（第 15-18 行）。

### 1.4 `backend/data/local-knowledge-base.json`
- 顶层仅 `positions`（6 个岗位）+ `defaultResponse`。资源内嵌在各岗位 `resources` 数组中，**无独立的 `resourcePool` 字段**。

### 1.5 `backend/data/learning-resources.json`
- 含约 90 条资源（`resources` 数组），字段：`id/title/url/source/sourceName/type/level/skillTags/status/lastChecked/failCount`。其中约 37 条 B 站链接为 `search.bilibili.com` 搜索页（违反"禁止主页/合集链接"规范）。无 `backupUrl/practicePlan/recommendedTools`。

### 1.6 前端 `src/components/Planning.vue`
- "推荐资源库"视图（`currentNav === 'resource-lib'`）的 `resourceCards` computed（第 1666-1694 行）**仍调用本地 `findMatchingResources`**，未走后端。`defaultResourceCards` 显示"选择岗位以获取智能推荐"（即用户截图空白问题源头）。无 loading、无错误降级。

### 1.7 前端 `src/components/SkillRoute.vue`
- ✅ 已后端驱动：`fetchResources` 调用 `/api/resources/match-position`，含 `loadingResources` 区域锁定、加载提示横幅、技能面板内 loading、watch 自动触发。仅缺备用链接展示。

### 1.8 前端 `src/data/resources.js`
- 保留 61 条 `resourceDatabase` + `posSkillData`（73 岗位技能关键词）+ `findMatchingResources`（复杂本地匹配）。作为离线兜底保留。

### 1.9 `backend/data/position-skills.json`
- ❌ 不存在。需新建，作为 `/self-check` 遍历全量岗位的数据源。数据从前端 `src/data/positionSkills.js` 迁移（含 `positionGroups` + `positionSkillMap`，覆盖 56+ 岗位）。

### 1.10 `backend/server.js`
- 已挂载 `app.use('/api/resources', resourceRoutes)`，无需改动。

## 二、设计决策（Assumptions & Decisions）

| 决策点 | 选择 | 理由 |
|--------|------|------|
| 资源池数据来源 | 合并 `learning-resources.json`(90) + 前端 `resources.js` `resourceDatabase`(61) + `local-knowledge-base` 内嵌资源，去重后入 `resourcePool` | 最大化覆盖技能标签，避免重复建设 |
| 主数据源切换 | `local-knowledge-base.json` 的 `resourcePool` 升为主数据源；`learning-resources.json` 降为巡检状态记录（保留 `lastInspection` 等） | 符合需求"以本地静态库为核心" |
| B 站搜索链接处理 | 标记 `source: "bilibili-search"`，排序降权；优先用前端 `resourceDatabase` 中的 B 站直链替换；自检报告标记"待优化" | 无法自动获取真实视频 ID，务实降级 |
| L2 模型 | Coze（复用 `ai.js` 的 `callCozeWithKnowledge` 模式），prompt 强制生成"1 文档+1 视频+实战+工具" JSON | 需求明确要求 Coze |
| L2 失败降级 | Coze 配置缺失/无积分/令牌失效/网络异常/JSON 解析失败 → 直接 L3（仅本地资源），前端不报错 | 需求第 1、6 条 |
| 自检端点鉴权 | 暂不加鉴权（与现有端点一致），可选 `?token=` 简单校验 | 现有端点均无鉴权，保持一致 |
| 自检报告格式 | JSON：`{ summary, emptyPositions[], mismatchedResources[], invalidLinks[], bilibiliSearchLinks[] }` | 便于程序化处理和前端展示 |
| Planning.vue 改造 | 改为后端驱动（`/match-position`），保留 `findMatchingResources` 作降级兜底（`fetch` 失败时触发） | 与 SkillRoute 一致，保证零空白 |
| 链接动态校验性能 | 复用 `quickCheckLink` 3h 缓存 + `Promise.all` 并发，单链接 6s 超时 | 已有实现，性能可接受 |
| `backupUrl` 展示 | 资源卡片主链失效时自动切换 `backupUrl`（前端 `getResourceUrl` 逻辑） | 需求"每个视频配置备用链接" |

#### 3.3 新增 `generateCozeResources(skillName, positionKey)`（L2）
```javascript
async function generateCozeResources(skillName, positionKey) {
  if (!COZE_API_KEY || !COZE_BOT_ID) {
    console.warn('[Resources][L2] Coze 配置缺失，跳过')
    return null
  }
  const prompt = `为技能「${skillName}」生成 JSON 学习资源，严格格式：
  {"resources":[{"title":"","url":"https://","backupUrl":"https://","source":"official|bilibili|github","type":"官方文档|视频课程|实战项目","level":"入门|进阶","skillTags":["${skillName}"],"desc":"","practicePlan":["步骤1"],"recommendedTools":["工具1"]}]}
  要求：1条官方文档+1条B站单视频(非搜索页)+1条实战项目；链接必须真实可访问；2022年后教程。仅返回 JSON。`
  try {
    // 调用 Coze API（参考 ai.js 的 callCozeWithKnowledge 模式）
    const resp = await fetch(`${COZE_API_BASE}/v3/chat`, {
      method: 'POST',
      headers: { 'Authorization': `Bearer ${COZE_API_KEY}`, 'Content-Type': 'application/json' },
      body: JSON.stringify({ bot_id: COZE_BOT_ID, user_id: 'resource-gen', stream: false, additional_messages: [{ role: 'user', content: prompt, content_type: 'text' }] }),
      signal: AbortSignal.timeout(20000)
    })
    if (!resp.ok) { console.warn('[Resources][L2] Coze HTTP', resp.status); return null }
    const data = await resp.json()
    const text = extractCozeText(data)
    const json = parseJsonFromText(text)
    if (!json?.resources?.length) return null
    // 校验链接
    return json.resources.filter(r => r.url && /^https?:\/\//.test(r.url))
  } catch (e) {
    console.warn('[Resources][L2] Coze 调用失败:', e.message)
    return null
  }
}
```
- Coze 配置从 `process.env.COZE_API_KEY/COZE_BOT_ID/COZE_API_BASE` 读取（与 `ai.js` 一致）。
- 失败（配置缺失/HTTP 错误/超时/JSON 解析失败）统一返回 `null`，由 `matchSkillResources` 走 L3。

#### 3.4 重构 `matchSkillResources`（三级匹配）
- L1：`loadResourcePool().filter(r => isSkillMatched(r, skillName) && r.status !== 'invalid')` → `filterValidResources` 实时校验 → `hasTextAndVideo` 判定。
- L2：`generateCozeResources(skillName, positionKey)` → 若返回非空，`filterValidResources` 校验 → 合并去重 → `hasTextAndVideo` 判定。
- L3：合并 `getKnowledgeBaseFallback(positionKey, skillName)`，**保证至少返回 3 条资源**（终极兜底：从 `resourcePool` 取同岗位其他资源或通用高评分资源）。
- 日志：`[Resources][L1/L2/L3]` 标注层级，仅后端记录。

#### 3.5 新增 `/self-check` 自检端点
```javascript
router.get('/self-check', async (req, res) => {
  const posData = loadPositionSkills()  // 读 position-skills.json
  const pool = loadResourcePool()
  const report = { summary: { totalPositions: 0, passed: 0, emptyPositions: [], mismatchedResources: [], invalidLinks: [], bilibiliSearchLinks: [] }, details: [] }
  
  for (const group of posData.positionGroups) {
    for (const pos of group.positions) {
      report.summary.totalPositions++
      const skillMap = posData.positionSkillMap[pos.key]
      if (!skillMap) { report.summary.emptyPositions.push({ position: pos.label, reason: '无技能数据' }); continue }
      const allSkills = Object.values(skillMap).flat().map(s => s.name)
      const posDetail = { position: pos.label, positionKey: pos.key, totalSkills: allSkills.length, emptySkills: [], mismatched: [], invalidLinks: [] }
      
      for (const skillName of allSkills) {
        const matched = await matchSkillResources(skillName, pos.key)
        if (matched.resources.length === 0) {
          posDetail.emptySkills.push(skillName)
        } else {
          // 相关性校验：资源 skillTags 或 title 必须包含技能关键词
          const tokens = skillName.split(/[\/\s,，、（）()]+/).filter(t => t.length > 1)
          for (const r of matched.resources) {
            const relevant = isResourceRelevant(r, skillName, tokens)
            if (!relevant) posDetail.mismatched.push({ skill: skillName, title: r.title, url: r.url })
            // 链接校验
            const linkStatus = await quickCheckLink(r.url)
            if (linkStatus === 'invalid') posDetail.invalidLinks.push({ skill: skillName, title: r.title, url: r.url })
            // B 站搜索链接标记
            if (r.url.includes('search.bilibili.com')) report.summary.bilibiliSearchLinks.push({ position: pos.label, skill: skillName, title: r.title, url: r.url })
          }
        }
      }
      
      if (posDetail.emptySkills.length > 0) report.summary.emptyPositions.push({ position: pos.label, emptySkills: posDetail.emptySkills })
      report.summary.mismatchedResources.push(...posDetail.mismatched)
      report.summary.invalidLinks.push(...posDetail.invalidLinks)
      if (posDetail.emptySkills.length === 0 && posDetail.mismatched.length === 0 && posDetail.invalidLinks.length === 0) report.summary.passed++
      report.details.push(posDetail)
    }
  }
  res.json({ success: true, data: report })
})
```
- `isResourceRelevant(r, skillName, tokens)`：资源 `skillTags` 包含技能名，或 `title` 包含任一 token，视为相关。
- 报告字段：`summary`（通过数、异常岗位、不匹配资源、失效链接、B 站搜索链接清单）+ `details`（每岗位明细）。

#### 6.2 新增 `fetchResources` 函数
```javascript
const fetchResources = async () => {
  if (!selectedPosition.value) { resourceMap.value = {}; return }
  if (loadingResources.value) return  // 区域锁定
  loadingResources.value = true
  resourceError.value = false
  try {
    const skills = currentSkills.value.map(s => ({ name: s.name, level: s.level }))
    const res = await fetch('/api/resources/match-position', {
      method: 'POST', headers: { 'Content-Type': 'application/json' },
      body: JSON.stringify({ positionKey: selectedPosition.value, skills })
    })
    const data = await res.json()
    if (data.success) { resourceMap.value = data.data } else { resourceError.value = true }
  } catch (e) {
    console.error('[Planning] 资源加载失败，启用本地兜底:', e)
    resourceError.value = true  // 触发本地兜底，前端不弹报错
  } finally {
    loadingResources.value = false
  }
}
watch(selectedPosition, () => { fetchResources() })
onMounted(() => { if (selectedPosition.value) fetchResources() })
```

#### 6.3 改造 `resourceCards` computed
```javascript
const resourceCards = computed(() => {
  if (!selectedPosition.value) return defaultResourceCards
  if (loadingResources.value) return []  // 模板显示 loading 横幅
  
  // 错误降级：本地 findMatchingResources 兜底
  if (resourceError.value) {
    const userProgress = parseInt(localStorage.getItem('learningProgress_' + selectedPosition.value) || '0', 10)
    const matched = findMatchingResources(selectedPosition.value, userProgress)
    return (matched && matched.length) ? matched.map(toCard) : defaultResourceCards
  }
  
  // 后端数据 → 扁平卡片列表
  const cards = []
  for (const [skillName, skillData] of Object.entries(resourceMap.value)) {
    for (const res of (skillData.resources || [])) {
      cards.push({
        id: res.id,
        title: res.title,
        desc: res.desc || skillData.practiceTip || '',
        typeLabel: res.type,
        url: res.url,
        externalUrl: res.url,
        backupUrl: res.backupUrl || '',
        practicePlan: res.practicePlan || skillData.practiceTip ? [skillData.practiceTip] : [],
        recommendedTools: skillData.tools || res.recommendedTools || [],
        matchedSkills: [skillName],
        featured: cards.length === 0
      })
    }
  }
  return cards.length > 0 ? cards : defaultResourceCards
})
```

## 六、风险与缓解

| 风险 | 缓解 |
|------|------|
| `resourcePool` 合并后字段缺失 | 统一补默认值（`backupUrl:''`、`practicePlan:[]`、`recommendedTools:[]`），自检报告标记缺失项 |
| B 站搜索链接无法自动替换为直链 | 标记 `bilibili-search` 降权，自检报告列出待优化清单，后续人工或 Coze 补充 |
| Coze 无积分/令牌失效 | L2 返回 `null` 直接走 L3，前端无感 |
| 链接实时校验慢（90+ 链接） | `quickCheckLink` 3h 缓存 + 6s 超时 + `Promise.all` 并发 |
| 自检耗时长（56 岗位 × 多技能） | 端点异步执行，响应可能 30s+，前端可加"检测中"提示；或后续改异步任务+结果查询 |
| `Planning.vue` 本地兜底数据过时 | 保留 `findMatchingResources` 仅作降级，主流程走后端 |
